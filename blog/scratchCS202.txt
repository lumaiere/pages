Course:

Course framing:

At this point, students know how programs work. Now they need to learn how people build software that other people can survive.

Course map:

Episode 1 - Version Control and Change Management - https://medium.com/@DaveLumAI/cs202-episode-1-version-control-and-change-management-or-how-teams-remember-what-happened-before-068050d8d334
How teams remember what happened and who introduced the chaos

Focus:

* version control concepts
* commits, branches, and merges
* collaboration and history
* why backup and source control are not the same thing

Why here:
Because real software is changed more often than it is written fresh.

Episode 2 - APIs and Program Boundaries - https://medium.com/@DaveLumAI/cs202-episode-2-apis-and-program-boundaries-or-how-software-talks-without-everyone-crying-1da7a2f92fe4

Focus:

* interfaces and contracts
* function APIs vs service APIs
* inputs, outputs, and assumptions
* breaking systems into parts that can cooperate

Why here:
Because software becomes real systems through boundaries.

Episode 3 - Error Handling and Defensive Programming - https://medium.com/@DaveLumAI/cs202-episode-3-error-handling-and-defensive-programming-or-hope-is-not-an-exception-strategy-2b093be55f2f
Hope is not an exception strategy

Focus:

* recoverable vs fatal errors
* validation and failure modes
* graceful degradation
* designing for things to go wrong in ordinary ways

Why here:
Because reliability begins with not acting surprised when reality happens.

Episode 4 - Refactoring and Code Smell - https://medium.com/@DaveLumAI/cs202-episode-4-refactoring-and-code-smell-or-how-to-improve-code-without-setting-fire-to-the-035aeb2902e5
How to improve code without setting fire to the part that already works

Focus:

* common signs of bad structure
* safe improvement
* readability and maintainability
* why naming and duplication matter more than people admit

Why here:
Because code ages, and students need to learn how to help it age less badly.

Episode 5 - Build Systems and Dependency Management - https://medium.com/@DaveLumAI/cs202-episode-5-build-systems-and-dependency-management-or-how-software-becomes-a-thing-you-can-b4a0b8dca81b
How software becomes a thing you can actually run on purpose

Focus:

* compilation pipelines
* package dependencies
* reproducible builds
* why installing one library can summon six hundred of its friends

Why here:
Because software engineering includes getting the software into existence repeatedly.

Episode 6 - Debugging at Scale - https://medium.com/@DaveLumAI/cs202-episode-6-debugging-at-scale-or-when-the-bug-is-not-in-one-line-but-in-the-relationship-329b442af6c5
When the bug is not in one line but in the relationship between eight ideas

Focus:

* tracing across modules
* logging and instrumentation
* narrowing failure scope
* systematic debugging in larger codebases

Why here:
Because larger systems fail in more creative ways.

Episode 7 - Software Engineering as Team Sport - https://medium.com/@DaveLumAI/cs202-episode-7-software-engineering-as-team-sport-or-the-social-layer-of-technical-work-where-e5c4fd852798
The social layer of technical work, also known as where half the problems move

Focus:

* code reviews
* documentation
* task breakdown
* collaboration and communication

Why here:
Because most important software is built by groups, not lone cave wizards.
