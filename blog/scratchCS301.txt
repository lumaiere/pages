CS202 prior course reference:
Software Design and Development Practice

Course framing:
At this point, students know how programs work. CS202 teaches them how people build software that other people can survive. It moves from isolated programming into real-world software practice: teams, tools, boundaries, errors, builds, maintenance, debugging, and collaboration.

CS202 Episode Summary:

Episode 1 - Version Control and Change Management
Link:
https://medium.com/@DaveLumAI/cs202-episode-1-version-control-and-change-management-or-how-teams-remember-what-happened-before-068050d8d334

Summary:
Introduces version control as the memory system of software teams. Students learn commits, branches, merges, history, and collaboration, along with the crucial difference between source control and ordinary backup. The episode frames software as something that changes constantly, often by many people, and teaches students how teams preserve sanity while the codebase evolves.

Continuity value for CS301:
CS301 should assume students understand that real systems have history, change over time, and require disciplined change management rather than heroic folder-copying rituals.

Episode 2 - APIs and Program Boundaries
Link:
https://medium.com/@DaveLumAI/cs202-episode-2-apis-and-program-boundaries-or-how-software-talks-without-everyone-crying-1da7a2f92fe4

Summary:
Explains how software components communicate through interfaces and contracts. Students learn the difference between function APIs and service APIs, how inputs and outputs define expectations, and why assumptions at boundaries can either make systems cooperate beautifully or collapse into interpretive dance with stack traces.

Continuity value for CS301:
CS301 should build on the idea that larger systems are made from boundaries, contracts, and negotiated responsibilities between components, services, teams, and infrastructure.

Episode 3 - Error Handling and Defensive Programming
Link:
https://medium.com/@DaveLumAI/cs202-episode-3-error-handling-and-defensive-programming-or-hope-is-not-an-exception-strategy-2b093be55f2f

Summary:
Teaches students that failure is not a surprise guest. It is part of the design space. The episode covers recoverable versus fatal errors, validation, ordinary failure modes, graceful degradation, and defensive programming habits that help software survive contact with users, networks, files, time, and the thousand tiny raccoons living in production.

Continuity value for CS301:
CS301 should assume students can think about failure explicitly and should expand that into system-level reliability, observability, recovery, security, and operational design.

Episode 4 - Refactoring and Code Smell
Link:
https://medium.com/@DaveLumAI/cs202-episode-4-refactoring-and-code-smell-or-how-to-improve-code-without-setting-fire-to-the-035aeb2902e5

Summary:
Introduces refactoring as disciplined improvement rather than recreational demolition. Students learn to recognize code smells, improve structure safely, value readability and maintainability, and understand why naming, duplication, and tangled responsibilities quietly turn future development into an unpaid escape room.

Continuity value for CS301:
CS301 should assume students understand that code has a long-term shape and that architecture, design patterns, modularity, and technical debt all grow from the same concern: making change survivable.

Episode 5 - Build Systems and Dependency Management
Link:
https://medium.com/@DaveLumAI/cs202-episode-5-build-systems-and-dependency-management-or-how-software-becomes-a-thing-you-can-b4a0b8dca81b

Summary:
Explains how source code becomes something that can actually run on purpose. Students learn about compilation pipelines, package dependencies, reproducible builds, and the strange modern reality that installing one library may summon six hundred tiny contractual houseguests. The episode connects tools, automation, environments, and repeatability.

Continuity value for CS301:
CS301 should build on this by treating build pipelines, deployment, dependency risk, containers, CI/CD, and supply-chain awareness as part of serious software system design.

Episode 6 - Debugging at Scale
Link:
https://medium.com/@DaveLumAI/cs202-episode-6-debugging-at-scale-or-when-the-bug-is-not-in-one-line-but-in-the-relationship-329b442af6c5

Summary:
Moves debugging beyond the single suspicious line. Students learn how failures emerge across modules, layers, assumptions, logs, timing, and interactions. The episode emphasizes tracing, instrumentation, narrowing scope, systematic investigation, and resisting the ancient developer temptation to stare angrily at the wrong file for two hours.

Continuity value for CS301:
CS301 should assume students can reason across larger systems and should extend that into distributed systems, production observability, incident response, monitoring, testing strategy, and architecture-level diagnosis.
